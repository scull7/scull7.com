## why
After a T-16 named session, recruiter agents need required-set progress on every ask and a single `interview.completed` webhook when the locked five-item set first becomes empty. T-19 hold is later.

## scope_in
- Required-set matching as a calculation over session + config.
- `required_progress` / `required_remaining` on every ask JSON.
- Default ids: current_work, leadership, systems, wants_next, hiring_timeline.
- Recruiter hiring-timeline statement (their words, not a resume citation).
- Configurable `INTERVIEW_REQUIRED_QUESTIONS` (CSV of default ids or a JSON array).
- Isolated webhook POST of `interview.completed` exactly once when a session with `callback_url` first completes the set.
- Turso persistence of completed ids and recorded hiring timeline.

## scope_out
- T-19 `create_hold` / GCal / hold mail / `booking.requested`.
- GET-session.
- Reopening 2026-08-22 locks.
- Hand-authored JavaScript.
- New third-party packages.

## acceptance_criteria
- [ ] After a T-16 session, every ask JSON includes required_progress (completed ids) and required_remaining (remaining ids). Default remaining: current_work, leadership, systems, wants_next, hiring_timeline. A refuse does not add to progress or remove from remaining.
- [ ] Four cited items plus recruiter hiring-timeline statement (their words, not a resume quote) marks the set complete (required_remaining empty). A later ask does not mark completeness a second time.
- [ ] Four cited without timeline: remaining still includes hiring_timeline; not complete; interview.completed not sent.
- [ ] Timeline alone: remaining still includes current_work, leadership, systems, wants_next; not complete; interview.completed not sent.
- [ ] Hiring timeline is recruiter fact: recording ask cited false, not a resume/page citation; answer contains their words; later ask echoes hiring_timeline with those words. No invented career fact.
- [ ] INTERVIEW_REQUIRED_QUESTIONS is CSV of those default ids or a JSON array. Setting current_work,hiring_timeline shrinks first-ask remaining to those two; completing cited current work + timeline completes the set. Empty/unset restores five.
- [ ] If session has callback_url, that URL receives interview.completed exactly once on the first completing ask. No booking.requested. If no callback_url, no webhook, set still complete.
- [ ] Completing ask still succeeds if interview.completed POST fails. Completeness not rolled back.
- [ ] This card does not call create_hold and does not require verify, book token, GCal, or hold mail.
