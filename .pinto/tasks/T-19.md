## why
After T-17 verify and T-18 required-set complete, recruiter agents create a tentative calendar hold with a book token. Cap/ban/refuse are calculations; the booking backend, Resend HTTP, and webhook POST are isolated actions.

## scope_in
- Book-token-only `POST /interview/holds` (start + book_token, optional end). No session path param.
- Isolated booking-backend create/cancel, Nathan hold mail, and `booking.requested` webhook.
- Hold-cap, ban-address, ban-domain as calculations over store + config.
- Named errors: `required_incomplete`, `token_invalid`, `invalid`, `hold_cap`, `slot_unavailable`, `missing_env`.
- OpenAPI documents hold, verify, ban. MCP remains the five spec names.

## scope_out
- Firing `interview.completed` from create_hold.
- GET-session, delete-session, source-mint.
- Distinct unverified or not_found create_hold boxes (those are `token_invalid`).
- Hand-authored JavaScript.
- New third-party packages.

## acceptance_criteria
- [x] Valid book token + incomplete required set → 4xx/409 error=required_incomplete. No calendar booking, no Nathan hold mail, no booking.requested, no interview.completed, no hold-cap consume.
- [x] No / forged / empty / unknown book token → error=token_invalid. Same no-touch. Complete-set + no verify is this box. Unknown session is this box.
- [x] INTERVIEW_BOOK_TOKEN_TTL_MS=2000 then wait → token_invalid, no-touch. Default unset 1800000.
- [x] Missing/empty start → error=invalid, no-touch.
- [x] After T-17 verify + T-18 complete, create_hold(start + book token, no end) books the start on the configured calrs event type. calrs owns the meeting length, so the booked event is that event type's duration and a passed `end` does not change it; the stored hold row still uses start + INTERVIEW_HOLD_DEFAULT_SECONDS (default 1 hour) for cap math. MCP create_hold matches HTTP.
- [x] INTERVIEW_CAL_USERNAME / INTERVIEW_CAL_EVENT_SLUG change which calrs event type is booked, and INTERVIEW_CALENDAR_ID / INTERVIEW_HOLD_DEFAULT_SECONDS change the stored hold's calendar id and length, without a code change.
- [x] Work domain at most N active tentative holds (default 3). N+1st → hold_cap. INTERVIEW_HOLD_CAP changes N. Hold-cap refuse: no calendar booking, no Nathan hold mail, no booking.requested, no interview.completed, no extra cap slot.
- [x] Creating a hold emails Nathan (INTERVIEW_MAIL_TO default nathan@vegasbuckeye.com) with working ban-this-address and ban-this-domain links. After ban-address, new session from that address rejected. After ban-domain, new session from that work domain rejected.
- [x] callback_url receives booking.requested only when hold is created. Do not send interview.completed. No third event name.
- [x] Missing booking-backend env (INTERVIEW_CAL_API_URL, then INTERVIEW_CAL_USERNAME, then INTERVIEW_CAL_EVENT_SLUG) or mail sender → missing_env naming the first absent var. No fake hold persisted as success.
- [x] Mail-fail-after-create: present RESEND_API_KEY whose send HTTP fails after the calrs booking succeeds. Cancel the booking via its cancel token; book token remains usable; booking.requested not sent; hold-cap not consumed (INTERVIEW_HOLD_CAP=1 later success is still first of N).
- [x] A start that is not an open calrs slot → error=slot_unavailable (409), no-touch: no hold row, no Nathan hold mail, no booking.requested, no cap consume, book token still usable.
- [x] calrs answers HTTP 200 even when it refuses, so a response without a `/booking/ics/<token>` cancel token is never treated as a hold. The link is HTML-escaped in the response and still parses.
- [x] The configured calrs event type must not require confirmation; a pending response is refused loudly (invalid naming requires-confirmation) rather than stored as a hold that cannot be cancelled.
- [x] Contact nathan@vegasbuckeye.com. No street address. OpenAPI documents hold, verify, ban with required fields (hold request required: start, book_token) and named response properties. MCP remains exactly the five spec names.
