## why
After T-17 verify and T-18 required-set complete, recruiter agents create a tentative GCal hold with a book token. Cap/ban/refuse are calculations; GCal, Resend HTTP, and webhook POST are isolated actions.

## scope_in
- Book-token-only `POST /interview/holds` (start + book_token, optional end). No session path param.
- Isolated GCal create/cancel, Nathan hold mail, and `booking.requested` webhook.
- Hold-cap, ban-address, ban-domain as calculations over store + config.
- Named errors: `required_incomplete`, `token_invalid`, `invalid`, `hold_cap`, `missing_env`.
- OpenAPI documents hold, verify, ban. MCP remains the five spec names.

## scope_out
- Firing `interview.completed` from create_hold.
- GET-session, delete-session, source-mint.
- Distinct unverified or not_found create_hold boxes (those are `token_invalid`).
- Hand-authored JavaScript.
- New third-party packages.

## acceptance_criteria
- [ ] Valid book token + incomplete required set → 4xx/409 error=required_incomplete. No GCal, no Nathan hold mail, no booking.requested, no interview.completed, no hold-cap consume.
- [ ] No / forged / empty / unknown book token → error=token_invalid. Same no-touch. Complete-set + no verify is this box. Unknown session is this box.
- [ ] INTERVIEW_BOOK_TOKEN_TTL_MS=2000 then wait → token_invalid, no-touch. Default unset 1800000.
- [ ] Missing/empty start → error=invalid, no-touch.
- [ ] After T-17 verify + T-18 complete, create_hold(start + book token, no end) creates a tentative GCal event 1 hour on calendar id scull7.com (or INTERVIEW_CALENDAR_ID). Passing end uses that end. MCP create_hold matches HTTP.
- [ ] INTERVIEW_CALENDAR_ID / INTERVIEW_HOLD_DEFAULT_SECONDS change calendar and default length without a code change.
- [ ] Work domain at most N active tentative holds (default 3). N+1st → hold_cap. INTERVIEW_HOLD_CAP changes N. Hold-cap refuse: no event, no Nathan hold mail, no booking.requested, no interview.completed, no extra cap slot.
- [ ] Creating a hold emails Nathan (INTERVIEW_MAIL_TO default nathan@vegasbuckeye.com) with working ban-this-address and ban-this-domain links. After ban-address, new session from that address rejected. After ban-domain, new session from that work domain rejected.
- [ ] callback_url receives booking.requested only when hold is created. Do not send interview.completed. No third event name.
- [ ] Missing GCal creds or mail sender → missing_env. No fake hold persisted as success.
- [ ] Mail-fail-after-GCal: present RESEND_API_KEY whose send HTTP fails after GCal create. Cancel GCal; book token remains usable; booking.requested not sent; hold-cap not consumed (INTERVIEW_HOLD_CAP=1 later success is still first of N).
- [ ] Contact nathan@vegasbuckeye.com. No street address. OpenAPI documents hold, verify, ban with required fields (hold request required: start, book_token) and named response properties. MCP remains exactly the five spec names.
