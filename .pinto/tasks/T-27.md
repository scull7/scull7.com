## why
A hold row stays `tentative` in Turso forever. Cancelling the booking in calrs — from the dashboard, or by the guest's emailed link — never reaches us, so a released slot still counts against that work domain's active-hold cap. After three cancelled-and-forgotten holds a domain is locked out of booking with nothing on the calendar to explain why. Cancelling the T-19 proof booking put the first such row in production.

## scope_in
- Ask the booking port whether each active hold still exists before counting it against the cap.
- Mark holds that no longer exist as `cancelled` so the reconciliation is not repeated.
- calrs answer: `GET /booking/ics/{cancel_token}` is 200 when live and 404 once cancelled.

## scope_out
- A webhook or polling job from calrs back to scull7.com.
- Reconciling anything other than the cap path.
- Changing the cap default or its config.

## acceptance_criteria
- [x] The booking port gains an existence check; `capture()` answers from its recorded events and the calrs backend maps 200 to live and 404 to gone.
- [x] Counting active holds for a domain excludes holds whose booking no longer exists, and those rows are marked `cancelled` in the store.
- [x] A domain at the cap whose bookings were all cancelled in calrs can book again.
- [x] A hold whose booking still exists keeps counting; an existence check that errors is treated as still-live so a flaky backend cannot free the cap.
- [x] `npm run test:interview` green, with fixtures for the live, cancelled, and errored cases.
