## why
There is no `.github/workflows`; a PR can merge while `elm make`, `dune build @site`, `npm run build`, elm-test, or e2e is red.

## scope_in
- GitHub Actions workflow on `pull_request`.
- Pinned `run:` argv (exact strings, not echo-titled names): `npm run elm:make`, `npm run melange` (or `opam exec -- dune build @site`), `npm run build`, `npm run test:elm` (T-21), `npm run test:e2e` (`node e2e/run.mjs`, which starts Vite preview and T-22 cases), `npm run test:t13`.
- E2e step requires Playwright Chromium install **and** preview via `e2e/run.mjs` (not bare `node e2e/navigation.mjs` against a missing server).
- In-repo proof that a saboteur (documented `false` step or a broken named test) fails the **job**. This PBI does **not** claim GitHub UI “required check” / branch protection.
- Bound cold-start with in-repo GHA caches for npm/elm/opam **in GitHub Actions only**.
- Do not invent a second deploy path besides Netlify.

## scope_out
- routing / print / T-8 / new npm except elm-test (where relevant)
- Netlify dashboard opam cache (not an in-repo falsifiable artifact; cut from this slice)
- GitHub Pages / second CDN deploy
- GitHub branch-protection / “required checks” dashboard (out of slice, same class as cut Netlify cache)
- Re-opening T-11/T-12/T-13 except as `test:t13` + identity regression
- Hash routing; print CSS
- Waiting on T-24 (retry UX is not this gate)

## acceptance_criteria
- [ ] A workflow file exists under `.github/workflows/` whose `on` includes `pull_request`.
- [ ] That workflow’s `run:` (or `run: |`) lines include **these exact argv**, not a step *named* “elm make” that echoes: `npm run elm:make`; `npm run melange` **or** `opam exec -- dune build @site`; `npm run build`; `npm run test:elm`; `npm run test:e2e`; `npm run test:t13`. A stub `run: echo ok` or `run: echo elm make` **fails** this PBI.
- [ ] Before `npm run test:e2e`, the workflow installs Playwright Chromium (`npx playwright install --with-deps chromium` or `npx playwright install chromium` plus OS deps). The e2e step **is** `npm run test:e2e` / `node e2e/run.mjs` (build-optional + Vite preview + T-22 cases). Bare `node e2e/navigation.mjs` without preview **fails**. Omitting Chromium install **fails**.
- [ ] Those pinned steps do **not** use `continue-on-error: true` and do **not** swallow the exit code (`|| true`).
- [ ] `npm run test:t13` is a required pinned step; omitting it **fails**.
- [ ] **Saboteur (in-repo job failure, not GitHub UI):** a documented recipe shows that a non-zero from **each** of `npm run elm:make`, `npm run test:elm`, `npm run test:e2e`, `npm run test:t13`, `npm run melange` (or the pinned dune argv), and `npm run build` fails the **workflow job** (not a continued sibling). Recipe: temporarily replace that `run:` with `false`, **or** break a named T-21 assertion / T-22 e2e assert, then run the job (`act pull_request` if installed, or a throwaway-branch job log). Job conclusion is failure. This PBI does **not** claim a GitHub “required check” is red. An echo-titled or unpinned job **fails**.
- [ ] The workflow does not publish a second deploy (no `peaceiris/actions-gh-pages`, no `netlify deploy --prod` from this PBI). A new production deploy path **fails**.
- [ ] Identity lock still holds in the built `dist/index.html` after `npm run build`: `<title>Nathan Sculli</title>`; meta description, `og:description`, and `twitter:description` remain `Builder-leader · 20+ years · Rust · Distributed Systems`; `og:title` remains `Nathan Sculli — scull7.com`; Person JSON-LD still has `name` `Nathan Sculli`, `jobTitle` `Director of Engineering`, `worksFor` TensorWave with `https://tensorwave.com`, and `sameAs` `https://github.com/scull7` and `https://linkedin.com/in/scull7`.
