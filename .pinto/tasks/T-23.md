## why
There is no `.github/workflows`; a PR can merge while `elm make`, `dune build @site`, `npm run build`, elm-test, or e2e is red.

## scope_in
- GitHub Actions workflow on `pull_request`.
- Pinned `run:` argv (exact strings, not echo-titled names): `npm run elm:make`, `npm run melange` (or `opam exec -- dune build @site`), `npm run build`, `npm run test:elm` (T-21), `npm run test:e2e` (runs `E2e_run`, which starts Vite preview and the T-22 cases), `npm run test:t13`.
- E2e step requires Playwright Chromium install **and** preview via `e2e/run.mjs` (not bare `node e2e/navigation.mjs` against a missing server).
- In-repo proof that a saboteur (documented `false` step or a broken named test) fails the **job**. This PBI does **not** claim GitHub UI “required check” / branch protection.
- Bound cold-start with in-repo GHA caches for npm/elm/opam **in GitHub Actions only**.
- Do not invent a second deploy path besides Netlify.

## scope_out
- routing / print / T-8 / new npm except elm-test (where relevant)
- Netlify dashboard opam cache (not an in-repo falsifiable artifact; cut from this slice)
- GitHub Pages / second CDN deploy
- GitHub branch-protection / “required checks” dashboard (out of slice, same class as cut Netlify cache)
- Re-opening T-11/T-12/T-13 except as `test:t13` + identity regression
- Hash routing; print CSS
- Waiting on T-24 (retry UX is not this gate)

## saboteur recipe

Each pinned gate fails the **job**, not just a step: GitHub Actions stops a job on the
first non-zero `run:`, and no gate here softens or discards its exit status, so every
later gate is `skipped` rather than run. Two real job logs prove both failure classes.

| Proof | Recipe | Run | Result |
|---|---|---|---|
| missing binary | `elm` installed before `npm ci`, which prunes it | [33139978727](https://github.com/scull7/scull7.com/actions/runs/33139978727) | `elm make` **failure**, 5 later gates skipped, job failure |
| broken assertion | `Expect.equal "April 2024"` → `"Apr 2024"` in `tests/FormatTests.elm` | [33140427501](https://github.com/scull7/scull7.com/actions/runs/33140427501) | `elm tests` **failure**, 2 later gates skipped, job failure |

To reproduce for any other gate, on a throwaway branch either replace that step's `run:`
with `false` or break a named assertion it covers, then `gh workflow run CI --ref <branch>`
(the workflow also has `workflow_dispatch`, so no PR is needed) and delete the branch after.
Locally each gate's non-zero is already observable: `npm run test:elm` exits 2 on a broken
assertion, and `npm run test:e2e` exits 1 when a `e2e_keyboard.ml` assert is broken
(`e2e/keyboard FAIL` → `e2e/run FAIL`).

This card does **not** claim a GitHub "required check" or branch protection; that is a
repository setting, outside the slice.
