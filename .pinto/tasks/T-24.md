## why
A failed `/resume.json` fetch currently leaves a silent or thin shell; the terminal is the product, so the user must see a retryable failure in-buffer/statusline/cmdline.

## scope_in
- When Http get of `/resume.json` fails, the Elm shell keeps **`#vim-root` chrome up** (`.statusline` **and** `.cmdline` present) plus a visible failure — not a blank `#app`, not today’s thin `.buffer-body` “Failed to load resume.json” with no retry control.
- New documented retry command **`:reload`** (palette/command; does not exist today). It issues a new GET `/resume.json` **without** a full-page reload (`location.reload` / F5 is not the retry path).
- Faults in scope (all of them, not OR): Playwright `route.abort`, HTTP 404, HTTP 500, **and** HTTP 200 with invalid JSON / empty body.
- Retry while the fault remains still shows failure UX (no stale/partial resume). Offline banner **only** if it is a thin terminal message; otherwise cut.
- Minimal visual change: only what is required to show the failure in-terminal.
- Lands in the T-20 Shell modules, not a new god-file.

## scope_out
- routing / print / T-8 / new npm except elm-test (where relevant)
- Marketing chrome / second homepage / hero error page
- Headline / OG / JSON-LD rewrite
- Hash routing, print CSS, deep-link e2e
- Full-page reload as the retry
- Changing live buffer visual design except as required for in-terminal failure

## acceptance_criteria
- [x] **Chrome on failure:** under each fault below, the mount point rendered content (asserted null-safely: `Browser.element` **replaces** `#app` with the rendered root, so `#app` does not survive mount), the document is not a marketing landing, `#vim-root` exists, `#vim-root .statusline` exists, `#vim-root .cmdline` exists, and the visible terminal shows a failure **and** the retry command `:reload` (buffer or statusline or cmdline — the string `:reload` is user-visible so a tester does not need the diff). Today’s thin `#vim-root .buffer-body` text `Failed to load resume.json` with **no** `.statusline`, **no** `.cmdline`, and **no** `:reload` **fails**. A blank `#app` **fails**. A hero / “something went wrong” marketing page **fails**.
- [x] **Abort:** Playwright `page.route` abort of `/resume.json` produces the chrome+failure+`:reload` UX above. Skipping abort because 404 is green **fails**.
- [x] **404:** fulfill `/resume.json` with HTTP 404 produces the same chrome+failure+`:reload` UX. Skipping 404 because abort is green **fails**.
- [x] **500:** fulfill `/resume.json` with HTTP 500 produces the same chrome+failure+`:reload` UX. Skipping 500 because abort or 404 is green **fails**.
- [x] **200 invalid JSON:** fulfill `/resume.json` with HTTP 200 and a non-JSON or empty body produces the same chrome+failure+`:reload` UX — **not** a hung `Loading resume…`, **not** a blank `#app`, **not** a partial resume hero. Skipping this because abort/404/500 is green **fails**.
- [x] **Retry while still failing:** from abort or 404 or 500 failure, run `:reload` (type `:` then `reload` Enter, or the visible control that runs that command) while the route still fails. `#vim-root .statusline` and `.cmdline` remain; failure+`:reload` remain; `#buffer-body .hero h1` is **absent** (no stale/partial resume). Blank `#app` **fails**.
- [x] **Retry then success, not full reload:** from a failure state, fulfill `/resume.json` HTTP 200 with valid JSON, then `:reload`. A new GET `/resume.json` fires. Resume content renders in the terminal (`#buffer-body .hero h1` includes the fixture/name from that JSON). The page does **not** perform a full document load (`location.reload` / F5 / Playwright `page.reload` as the retry **fails**). URL stays the preview `/`.
- [x] Healthy path unchanged: with `/resume.json` HTTP 200, the Melange navigation suite passes inside `npm run test:e2e`. The card predated the move off `e2e/*.mjs`.
- [x] `npm run test:t13` exits 0.
- [x] `npm run build` exits 0.
