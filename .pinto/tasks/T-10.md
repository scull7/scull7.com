## why
A visitor can tell the resume is current from the statusline date, without a marketing widget or a fabricated timestamp.

## scope_in
- Surface `meta.lastModified` in-aesthetic on the **statusline** (date portion is enough, e.g. `updated 2026-08-13`). Decode it from JSON.
- Home help-strip may optionally show the same date; it is not required.
- Do not invent a date if the field is missing or unparseable.

## scope_out
- Person JSON-LD, OG/Twitter tags, `og.png`, marketing page.
- Non-terminal last-updated widget.
- Fabricating a date when `meta.lastModified` is missing.
- Changing `basics.label`. Valuation in chrome.
- Splitting `Main.elm`. New dependencies.

## acceptance_criteria
- [x] After resume.json loads, the statusline shows a last-updated date that equals the `YYYY-MM-DD` prefix of `meta.lastModified` (string prefix, not local-midnight conversion) and is not the stale `2026-07-12` once T-1 has landed.
- [x] Statusline contains the visible label+date token `updated YYYY-MM-DD` (e.g. `updated 2026-08-13` when `meta.lastModified` starts with `2026-08-13`).
- [x] If `meta.lastModified` is removed in a local fixture, the UI does **not** display a fabricated date.
- [x] Unparseable fixture: set `meta.lastModified` to `"not-a-date"`; the UI does **not** show a date (no Unix epoch, no `today()`, no leftover T-1 calendar day).
- [x] Last-updated chrome is statusline (and optionally the home help-strip), not a non-terminal widget.
- [x] This PBI does not add JSON-LD or change `og:image` / `twitter:image`.
