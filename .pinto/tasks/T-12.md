## why
Search engines and no-JS clients currently see an empty `#app`; they should read name, summary, contact links, and the three authorized jobs from JSON Resume without a second visual site.

## scope_in
- A documented in-repo build step (Node/Vite script or plugin already in this repo — no new third-party packages) that reads `public/resume.json` and writes a static HTML fragment into `index.html` so the production Vite build emits it in `dist/index.html`.
- The fragment is generated from JSON, not hand-copied career facts: `basics.name`, `basics.label`, `basics.summary`; `basics.email` as a `mailto:` `<a>`; `basics.url` and each non-empty `basics.profiles[].url` as plain `<a href>`; `work[0]` (TensorWave) name, position, dates, url, highlights; `work[1]` (Sub Zero Corp) name, position, dates, highlights; `work[2]` (Banner) name, position, dates, url, highlights.
- Place the fragment in **one designated region**: `<noscript id="crawlable-resume">…</noscript>` in `index.html` / `dist/index.html`. All crawlable-content ACs inspect **only** that element's inner HTML. JSON-LD (`<script type="application/ld+json">`) and `<meta>` / OG / `<title>` are **excluded** and do not satisfy content ACs.
- Non-empty contact and job URLs are real `<a href>` values taken from JSON. Empty JSON URL fields emit no `href` (including no empty/`#` wrappers). Later jobs (`work[3]` and beyond) are not in this fragment.
- `npm run build` and the Netlify path (`scripts/netlify-build.sh` → `npx vite build`) both produce the fragment; resume edits must not require hand-editing HTML facts. Overwrite-restore of this fragment from current JSON is in this PBI.

## scope_out
- `robots.txt` / `sitemap.xml` / canonical link (T-11).
- Dummy-token mutation / empty-URL / missing-job / invalid-JSON fixtures (T-13).
- Headline / `basics.label` / OG / JSON-LD rewrite; hero buttons, cards, “focus areas”, impact-snapshot chrome.
- Case studies, diagrams, blog, writing surface; hash/path routing; full SSR; PDF / `:print`.
- Restoring `nathansculli.com` (T-8). Splitting `Main.elm`, elm-test, GitHub Actions.
- New third-party dependencies. Inventing MW/rack/GPU counts or unpublished TensorWave internals.
- Changing the live Elm buffers’ visual design.
