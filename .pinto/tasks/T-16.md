## why
Recruiter agents need a real, discoverable way to start a named Turso-backed session and ask cited questions against the published corpus. T-15’s unblessed draft (PR 18) bundled verify/hold with this slice; T-16 is the first stacked card.

## scope_in
- POST `/interview/sessions` and MCP `start_interview` (company, role, recruiter_name, work_email, optional callback_url).
- POST `/interview/sessions/{id}/ask` and MCP `ask_nathan` against Turso-persisted sessions (fresh function instance).
- Cited Q&A from `/resume.json` and public pages; refuse unpublished facts.
- GET `/interview/resume` and GET `/interview/experience?q=`.
- Real OpenAPI at `/openapi.json` with named request/response properties.
- MCP at `/mcp` with exactly `start_interview`, `ask_nathan`, `request_verification`, `create_hold`, `get_resume`. The last two may fail closed.
- `/llms.txt` when-to-use distinguishes static resume vs interview-me.
- Turso only. `INTERVIEW_STORE=memory` does not satisfy the store.
- Configurable `INTERVIEW_FREE_EMAIL_BLOCKLIST` / `INTERVIEW_EMAIL_ALLOWLIST`.

## acceptance_criteria
- [ ] POST `/interview/sessions` with company, role, recruiter_name, work_email returns 201 JSON echoing those four, a session id, and callback_url when sent. verified false/absent. MCP `start_interview` echoes the same.
- [ ] A later POST `/interview/sessions/{id}/ask` (and MCP `ask_nathan`) on a fresh function instance echoes those stored fields (and callback_url if sent). Persist is Turso, not process memory. No GET-session.
- [ ] Missing or empty company/role/recruiter_name/work_email → 4xx error=invalid. No session id.
- [ ] Ask against a never-created id → 4xx/404 error=not_found.
- [ ] gmail/yahoo/hotmail/outlook.com/icloud rejected error=free_email. Allowlisted address on a blocked domain accepted. `INTERVIEW_FREE_EMAIL_BLOCKLIST` / `INTERVIEW_EMAIL_ALLOWLIST` change accept/reject without a code change.
- [ ] Ask current work (TensorWave/Relay), leadership scale, systems depth (Rust/distributed), what Nathan wants next → cited answer from `/resume.json` or a public page. Unpublished (salary, street address, invented next role) refused, not invented.
- [ ] Ask succeeds while unverified. No calendar hold.
- [ ] GET `/interview/resume` has TensorWave. GET `/interview/experience?q=TensorWave` returns non-empty results with source, path, quote including TensorWave. Non-matching q → `{"results":[]}`. Always-empty TensorWave fails.
- [ ] GET `/openapi.json` is OpenAPI 3.x. Session/ask/resume/experience have required request fields and named response properties. GET `/mcp` tools/list is exactly start_interview, ask_nathan, request_verification, create_hold, get_resume. start_interview, ask_nathan, get_resume match HTTP. The other two may fail closed.
- [ ] `/llms.txt` when-to-use distinguishes static resume vs interview-me. Contact nathan@vegasbuckeye.com. No street address.
- [ ] Missing `TURSO_DATABASE_URL` or `TURSO_AUTH_TOKEN` → session create error=missing_env. `INTERVIEW_STORE=memory` does not satisfy the store.
