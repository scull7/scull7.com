## why
A visitor in the vim shell can open the new crossr-skills project the same way they open cents — without leaving the terminal aesthetic.

## scope_in
- Catalog entry for `crossr-skills.md` only (sidebar, `:ls`, `:e` / `:open`, command-palette `:e` row).
- Buffer body mapped from the JSON `crossr-skills` project: name, one-liner, primary marketing URL, secondary GitHub URL. Docs path `/docs/` on that site may be linked from JSON, not invented.
- Same terminal chrome as cents (buffer tab + body + statusline).
- Help.txt and/or palette remain able to discover the new buffer (palette `:e` list is sufficient if `:ls` lists it).

## scope_out
- `philosophy.md` buffer (separate PBI).
- New ferro-wg buffer (OSS list only).
- `:mail`, last-updated chrome, JSON-LD, OG, PDF export.
- Christian / Father copy on the site.
- Marketing landing page or non-terminal chrome.
- Splitting `Main.elm`. New dependencies. Live GitHub activity.

## acceptance_criteria
- [ ] Sidebar buffer list includes `crossr-skills.md` (or the exact id chosen, visible as that label).
- [ ] `:e crossr-skills.md` (and `:open` / palette equivalent) opens a buffer showing the JSON one-liner and a link to `https://scull7.github.io/crossr-skills/`; GitHub `https://github.com/scull7/crossr-skills` is visible and comes from JSON.
- [ ] `:ls` lists `crossr-skills.md`. Command palette in `:` mode offers an `:e` row for it.
- [ ] Opening the buffer uses the same terminal chrome as cents (buffer tab + body + statusline); no second non-terminal layout.
- [ ] ferro-wg has no dedicated buffer; it remains on `opensource.md` only.
- [ ] This PBI does not add a `philosophy.md` buffer.
- [ ] Mutation fixture: in a local `resume.json`, change the `crossr-skills` project's `description` and stored URL field(s) to distinct dummy values, reload; the buffer body text equals the new description and every visible href equals the new stored URL(s) (not the previous T-1 values).
- [ ] Every `href` in the `crossr-skills.md` buffer is a URL already stored on that project object. The buffer does not invent a `/docs/` link or any other URL that is not on the object.
- [ ] Empty-description fixture: in a local `resume.json`, keep the `crossr-skills` project object present and set only its `description` to `""`; reload. `:e crossr-skills.md` still opens the buffer (project is present). The opened buffer body does not contain the authorized T-1 one-liner `Agent skills + harness for long-running coding agents (“forged in the Cross”)` and does not contain any other invented fallback description; the description slot is empty or omitted.
- [ ] Missing-project fixture: in a local `resume.json`, remove the `crossr-skills` object from `projects[]` and reload. Allowed outcomes: (a) `crossr-skills.md` is absent from sidebar, `:ls`, and palette `:e`, and `:e crossr-skills.md` does not open a buffer that displays any project copy; or (b) the buffer is still listed and, when opened, its body has no one-liner, no T-1 authorized copy, and no invented project description. Passing is not “hide the sidebar row while `:e` still shows invented/T-1 copy.”
- [ ] Empty-url: if a stored URL field on the present `crossr-skills` project is `""`, the buffer does not render a fake or placeholder link (`href`) for that field.
